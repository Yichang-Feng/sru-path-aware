## 0. 现状定性：哪些成功、哪些崩了

### 0.1 v1 的路径层是成功的，⛔ 不得回退

| 指标（干净 eval，200 局，同口径） | 旧策略 | v1 | 判定 |
|---|---|---|---|
| median `d_path` | 1.19 m | **0.36 m** | ✅ 质变 |
| p90 `d_path` | 2.17 m | **0.68 m** | ✅ |
| 路径项 / 直连项（每局） | 0.70 / 15.7 | **13.0 / 1.1** | ✅ 反转成功 |
| `explained_variance` | — | 0.913 | ✅ critic 健康 |
| `base_contact` | — | 0.537→0.369 | ✅ 改善 |

**"贴线走"已经学会。** 后续所有改动必须保住 median `d_path` ≤ 0.5 m。

### 0.2 崩掉的是三件事，共享同一个规格错误模式

| # | 现象 | 每局代价 |
|---|---|---|
| **P-1** | 到目标附近绕圈刷分，不停稳 | SR 0.480 → **0.105**；timeout 0.395 → **0.71** |
| **P-2** | 朝向与路径差大时原地不动 / 缓慢倒车 | 约 1/3 回合初始 \|Δψ\|>120° |
| **P-3** | 楼梯前（需转向+爬升+再转向）原地不动 | stairs+带楼梯 maze ≈ **60% tile** |

**共同根因**：v1.0 规格在"移除坏激励"时，没有同步"补上缺失激励"，留下梯度真空，策略用未预期的方式填上（绕圈 / 冻结 / 倒走）。

> **不变量（贯穿全文）**：**所有正奖励必须是势函数**（单调、有界、望远镜求和，总量只取决于起终点）。**状态占用型正奖励（在某区域每步付钱）在目标附近必须为 0，只允许负项。**

## 1. 问题 P-1：目标附近"旅馆"

### 1.1 现象与指纹

`b2w_pathfix_v1` 200 局最长驻留连击分布：

```
0 步 93 局 / 6 步 22 局 / 7 步 53 局 / 8 步 17 局
```

**53 局卡在 7 步——差一步就成功，策略在主动规避第 8 步。** 旧策略分布是 `7步18局 / 8–11步79局`（会停下来）。

圈内速度 p50：旧 **0.48 m/s** → v1 **1.10 m/s**。

### 1.2 机制：拆掉了唯一的防刷分封顶

| | 旧 run | v1 |
|---|---|---|
| `reach_goal` | 10×0.2 = **2.00**/步 | 2×0.2 = 0.40/步 |
| `tight`（d≈0.3） | 1.5×(0.41/0.1)×0.2 = **1.23**/步 | 0.75×(0.41/0.2)×0.2 = 0.31/步 |
| `soft` | 0.05/步 | 0.05/步 |
| **合计** | **3.28/步** | **0.84/步** |
| **封顶** | latch：首次触圈后 20 步**强制终止** | 连续驻留：**无上限** |
| **旅馆容量** | 3.28×20 = **65.6** | 0.84×450 = **378** |

每步收入砍了 3.9 倍，封顶拆了 22.5 倍，**净容量涨 5.8 倍**。旧 run 的 latch bug 一直在充当意外的防刷分阀门。

**规格意图与代码不一致的证据**——`B2WRewardsCfg` docstring 原文：

> `reach_goal : +2.0 per step inside 0.5 m (**during the dwell**) ~+3`

意图是"只在 8 步驻留期间付 ~+3"，**代码里没有任何东西把它限制在驻留期间**。实测 +16.03。

### 1.3 ⛔ 速度门（报告 V1.1 方案）不足以修好

给三项加 `max_speed=0.5` 后：
- 慢速绕圈仍拿 0.84/步（门只要求 <0.5，不要求 =0）；
- **驻留计数只看距离、不看速度** → 慢速待 8 步就成功终止 → 策略必须每 ≤7 步主动出圈重置；
- d=0.3 出到 0.5 外，0.4 m/s 下约 3 步，回程 3 步 → 周期 ≈13 步，其中 ~9 步有收入；
- **摊薄 ≈0.58/步 × 450 ≈ 262**，而完成 = 25 + 8×0.84 ≈ **31.7 然后结束**。

**旅馆仍是完成的 8 倍。** 速度门只让绕圈变慢，不改变"完成即终止"的结构性劣势。

### 1.4 正确修法：目标附近正收入归零

**端点锁定（v1 Stage B 已做）是这条修法安全的前提**：路径最后一点就是目标，路径进度一路付到目标脚下（最后 0.5 m 付 0.6），**不存在"最后一段没有梯度"的探索空洞**。

| term | v1 | **V1.1** |
|---|---|---|
| `reach_goal` | 2.0 | **0.0** |
| `reach_goal_xy_tight` | 0.75 | **0.0** |
| `reach_goal_xy_soft` | 0.25 | **0.0** |
| `velocity_at_goal` | 未注册 | **−0.2**（`mdp.velocity_at_goal_penalty`，仓库已有） |
| `goal_reached_bonus` | 25 | **25 不变** |
| 超时成功判据 | 当步在圈内即算成功 | **恒记 0** |

> `weight=0` 时 `RewardManager` 直接跳过该项，**无需改 `rewards.py`**，最小 diff、可回退、Go2W 不受影响。

**修好后经济学**：

| 行为 | 回报 |
|---|---|
| 沿路径到目标 + 完成驻留 | 24.8 + 2.3 + 25 − 4 ≈ **+48** |
| 到目标绕圈到超时 | 24.8 + 2.3 − 10 − 4 − 速度罚 ≈ **+13** |
| 停在出生点 | **−10** |

完成比绕圈多 35 分，且不存在任何可刷的正项；抗站桩由路径进度保住。

## 2. 问题 P-2：转身冻结 / 缓慢倒车

### 2.1 现象

- 朝向 ≈ 终点方向、但与路径切向差大 → 原地不动
- 初始朝向与路径相反 → 原地不动，甚至缓慢倒着走
- **加入路径前没有这个现象**

### 2.2 机制一：v1 只剩一条朝向梯度，且指向终点

| 信号 | 对朝向的梯度 | 指向 |
|---|---|---|
| `progress_along_path` 1.2/m | **0**（转身时投影不动） | — |
| `path_deviation_penalty` | **0**（原地转身位置不变） | — |
| `progress` 0.15/m | **有**，cos 型 | **终点** |
| `heading_alignment` / `heading_progress_to_goal` | 仓库有，**B2W 未注册** | — |

`B2WRewardsCfg` 全表确认：**没有任何一项奖励"对准路径切向"。** "朝向≈终点方向"是奖励函数唯一的朝向最优解。

> v1.0 把 `progress` 1.5→0.15 时，只核算了它对"绕路 vs 直连"的**位置**激励，忽略了它同时是**唯一的朝向塑形信号**。

### 2.3 机制二：转身是 4 秒零收入真空

ω 上限 1.0 rad/s（`policy_scaling=[1.5,1.0,1.0]`），180° 需 3.14 s + 低通爬坡（α∈[0.1,0.6]）≈ **19 步 / 3.8 s**。这 19 步：路径进度 0、直连进度 0、偏差惩罚 0 → **合计收入 0，且没有任何一步告诉你"转对了"**。

### 2.4 机制三：硬门 + 静态路径 = 不可逆悬崖

不转身直接走（v=0.83 m/s，横向偏差以 v·sinΔψ 增长，出 **0.8 m 支付门**后收入永久归零，路径不重规划）：

| Δψ | 出门耗时 | 出门前投影推进 | 总路径收入 | 之后 |
|---|---|---|---|---|
| 30° | 1.93 s | 1.39 m | **+1.67** | 永久 0 |
| 60° | 1.11 s | 0.46 m | **+0.55** | 永久 0 |
| 90° | 0.96 s | ≈0 | **≈0** | 永久 0 |
| 180° | — | 0（后退投影） | 0 | 永久 0 |

**站着不动**：d_path≈0，无惩罚，只欠 −10 超时。
**乱走**：+0.5~1.7 然后永久断供，叠加偏差惩罚 + 37% 摔倒风险（−10）。

→ **冻结是吸收态旁的平台**：保住留在走廊内的期权，任何错误方向的平移都不可逆地 forfeit 全部路径收入。

**新旧 MDP 的本质差别**：旧版直连奖励是平滑 cos、无悬崖，转错随时可转回来继续赚；新版硬门 + 静态路径创造了吸收失败态，**却没有给避免进入它的塑形梯度**。

### 2.5 机制四：倒走是当前奖励下的合法最优替代

朝向差 180° 时，**倒着走 = 沿路径前进**：投影推进、d_path≈0、门开着 → **照付 1.2/m**。而 `backward_movement_penalty` 权重是 **0.0**（base cfg −0.0，curriculum 500 步后置 0）。

慢，是因为低层对负 vx 跟踪差 + 深度相机朝前（倒走全盲）→ 折中成"缓慢倒车"。

### 2.6 为什么"再多训几轮"不会好

- 180° 转身需 **19 步相干 ω 指令**。σ_ω≈0.64 零均值噪声经低通后，4 s 净偏航 std ≈ 25° → 180° 是 **~7σ 事件**，基本采样不到。
- 初始 yaw ~ U(−π,π)，约 1/3 回合 \|Δψ\|>120°。4000 iter ≈ 15 万回合，其中 ~5 万本该提供样本 → **不是样本量问题，是奖励里没有这个梯度**。
- σ 日程还在往下压，探索只会更少。

### 2.7 修法

**A. 路径切向朝向势函数（主修）**

```python
def heading_progress_to_path(env, command_name="robot_goal", lookahead=1.5):
    g = env.command_manager.get_term(command_name)
    # 复用 Stage E 已算好的局部路径插值，零额外开销
    p = g.get_local_path_point(lookahead)              # (B,3) body frame
    err = torch.atan2(p[:, 1], p[:, 0]).abs()          # [0, pi]

    if not hasattr(env, "_prev_path_heading_err"):
        env._prev_path_heading_err = err.clone()
        return torch.zeros_like(err)
    prog = env._prev_path_heading_err - err
    env._prev_path_heading_err = err.clone()
    prog[env.episode_length_buf <= 1] = 0.0            # reset 清零
    prog = torch.clamp(prog, -1.0, 1.0) / env.step_dt

    fade = torch.clamp(g.get_remaining_path_length() / 1.0, 0.0, 1.0)  # 末端 1 m 淡出
    return fade * prog
```

**weight = 1.0**。三条关键性质：

1. **势函数**：整局总额 = \|Δψ₀\| − \|Δψ_T\| ∈ [−π, π]，**有界、不可刷分**（来回摆头净收益 0），符合 §0.2 不变量。
2. **量级正好**：ω=1 rad/s → 每步 Δ\|Δψ\|=0.2 rad → 收入 **0.2/步**，与正常行驶路径收入 0.20/步同量级；180° 转身共 **+3.14**，立刻到账。
3. **压过倒走**：4 s 转身赚 3.14；同期倒走 0.3 m/s×4 s=1.2 m → 1.44。**转身成为严格更优**，⛔ 无需启用 backward penalty（会封死死胡同脱困）。

用 **1.5 m** 前视（不是瞬时切向、也不是 1.0 m）：给约 1.8 s 提前量；门洞内该点落在门里 → 朝向正确。**朝向塑形用短 carrot 是安全的，位置约束仍由路径进度主导。**

可选：relax 段权重 ×0.5，避免绕障时朝向被过度约束。

**B. 显式朝向误差观测（+2 维）**

`[cos Δψ_path, sin Δψ_path]`，与 A 用同一个 p。这是伺服的**误差量**；当前策略必须从 `path_embed(32)` ⊕ proprio 自己解算，而路径**不进 RNN**、只在 MLP 前拼接。仓库已有 Go2W 的 `target_heading_delayed`（cos/sin 范式）可照搬。

**C. 首点方向退化修正（免费）**

`path_dirs = path_b_unscaled / (norm + 1e-9)`：路径首点 = spawn，机体系下 ≈ 0 → **方向向量退化为 0，不是单位向量**。局部观测第 0 点永远在机器人身上，永远退化。修正：`norm < 0.05` 时用该段切向替代。

## 3. 问题 P-3：楼梯前冻结

### 3.1 场景

沿路径东→西行进，终点在北侧高台，需**左转 → 上楼梯 → 右转**。机器人在楼梯前原地不动。

### 3.2 硬事实：楼梯几何（`terrain_constants.py::StairConfig`）

```
NUM_STEPS = 5,  STEP_HEIGHT_METERS = 0.2
SINGLE_CELL_PIXELS = 20 (=2.0 m),  step_resolution = 20//5 = 4 px = 0.4 m
```

→ **5 级 × 0.2 m 踢面 / 0.4 m 踏面，总跑长 2.0 m、爬升 1.0 m，坡度 26.57°，弧长 2.24 m，整段楼梯装在一个 2 m 迷宫格里。**

### 3.3 关键推导：楼梯弦**必然**被误判为不可通行

| 量 | 值 |
|---|---|
| PRM `max_height_diff` | 50 单位 × 0.005 = **0.25 m** |
| 单级踢面 | 0.2 m = 40 单位 < 50 ✓ → **PRM 能规划上楼梯** |
| 15 点路径点间距（21 m / 14 段） | **≈1.5 m** |
| 落在整段楼梯上的点数 | 2.24 / 1.5 ≈ **1–2 个** |
| 一条 1.5 m 弦跨过楼梯的高差 | 1.5 × sin26.57° = **0.671 m = 134 单位** |

**134 ≫ 50 → 每一条跨越楼梯的重采样弦都会被判不可通行。这不是概率事件，是几何必然。**

**这解释了报告里一直没解释的 `invalid_seg_frac = 0.22`**（预期 5–10%，注入只贡献 ~2%）：stairs tile 30% + maze 开了 `add_stairs_to_maze=True` 再 30% → **六成 tile 有楼梯**，每处贡献 1–2 个假无效段，量级正好对得上。

> ⚠️ **标注**：`is_traversable` 是否用端点高差判定，尚未读 `prm.py` 核实 → **P0 必测项 D2**。但 0.671 vs 0.25 是配置里的确定值。

### 3.4 后果链：在唯一必须精确对齐的地方给出错误许可

```
楼梯弦 Δh=0.67 > 0.25  →  seg_passable = False（假阴性）
                       →  楼梯处 clearance 小 → pinch = True
relax bug: (inv|left|right) & ~pinch
                       →  inv ∧ pinch → relax = False → 走廊惩罚照常开
seg_gate: inv → max(1.6, push+0.6) = 1.6 m → 支付门反而放宽
```

**策略同时收到两个矛盾信号："偏离 0.5 m 就罚你" + "偏离 1.6 m 也照付进度"，而且这段路被标记为"不可通行、你可以离开路径"。** 楼梯恰恰是**绝对不能离开路径**的地方（旁边就是 1 m 落差）。

### 3.5 经济学：这里的冻结**不是**奖励最优（与 P-1 性质不同）

楼梯脚剩余路径 ~7 m + 25 bonus ≈ 33.4 分待领：

| 真实上楼成功率 p | 尝试期望 | 站着不动 |
|---|---|---|
| 0.4 | **+7.4** | −10 |
| 0.2 | −1.3 | −10 |
| 0.05 | −7.8 | −10 |
| 0.02 | **−9.1** | −10 |

**只要 p > 0.05，尝试就优于冻结。** 策略选择冻结 = 在说"我实际上楼成功率 ≈ 2%"。

**这是能力问题，但被奖励结构锁死**：

```
不会上楼 → 尝试期望为负 → 不尝试 → 永远采不到成功样本 → 不会上楼
```

打破这个环需要**不依赖"走完整套动作"就能拿到钱**的梯度。当前没有：

| 动作前缀 | 当前收入 |
|---|---|
| 减速 | 0 |
| 转 90° | **0**（路径项纯位置信号） |
| 精确对准 | 0 |
| 缓慢爬升 | 1.2/m，但 0.2 m/s → **0.048/步**（平地 0.2/步） |
| 顶端再转 90° | 0 |

**整套前缀是奖励真空，唯一有钱的部分在最慢、最危险的中段。**

### 3.6 三个楼梯口特有的放大器

**(a) 走廊宽度 × 角速度上限 ⇒ 必须减速，但只给 1 秒**

R = v/ω。v≈0.83、ω_max=1.0 → **R = 0.83 m ≈ 支付门 0.8 m** → **全速转 90° 必然出走廊**。要留在 corridor 内必须降到 ≤0.3 m/s（R=0.3 m）。

冲过拐角后到拐点距离以 0.83 m/s 增长 → **0.96 s（5 步）后支付门永久关闭**。低通 τ = −0.2/ln α ∈ [0.087, 0.39] s，加低层跟踪与惯性，实际制动 0.5–1 s。

**当前奖励在拐角前一路付钱让它全速冲，然后门在 1 秒内拍死。没有任何一项奖励"提前减速"。**

**(b) 角度容差**：20 cm 踢面对轮腿接近轮径量级。斜切进入时左右轮不同时接触踢面 → 偏航扰动 → `base_contact`（0.369）或 `large_pitch`（0.091，26.57° 距 40° 阈值只剩 13° 裕量）。**楼梯口角度容差远小于平地走廊**——平地差 20° 可 crab 回来，楼梯口差 20° 直接卡轮。

**(c) 90° 拐角弦切 ≈ 0.53 m**：1.5 m 间距、90° 拐角，弦到拐点最近距离 = 0.75×0.75/√(0.75²+0.75²) = **0.53 m**，占 2 m 楼梯口宽度的 **26%**。报告"切角 ≤0.2 m"应是均值/缓弯统计，**直角处不是这个数**。贴弦走 = 斜切进楼梯口，正好触发 (b)。

### 3.7 ⚠️ 必须先排除的执行器假设（否则改奖励全白费）

**B2W 能不能原地转身？**

反证据：报告里它在目标附近**以 1.10 m/s 画圈**——那是 R≈1.1 m 的**大半径弧线转弯**，不代表低速紧转能力。楼梯口需要 v≈0.2、ω≈0.8 的**紧转**。

若低层 `policy_b2w_new_2.pt` 在 vx→0 时 ω 跟踪严重衰减，**高层无论怎么被奖励都转不过来**，冻结是物理结果。这也能一并解释 P-2 的"开局朝向相反时不动、甚至缓慢倒车"（倒车是有 vx 的动作，紧转是 vx≈0 的动作）。

→ **P0 阻塞项 D1。**

## 4. 跨问题的已证实缺陷

### 4.1 `relax` 掩码方向反了（报告数字已定量证实）

规格应为 `inv | ((left|right) & ~pinch)`，实现是 `(inv|left|right) & ~pinch`。

**验证**：`invalid_seg_frac = 0.22`，`relax_frac = 0.087`。若公式正确，relax 必然 ≥ inv。现在 relax 只有 inv 的 40% → **约 13% 的全部路段是"不可通行却仍被走廊惩罚"**，正在惩罚正确的避障行为。

⚠️ **两个指标必须分列**：`invalid_raw_frac` 是**路径质量断言**（膨胀不改变它）；`relax_mask_frac` 是**故意放宽的区域**。混为一谈会让真退化被掩盖。

### 4.2 σ 日程与 4000 iter 严重错配

配置 `start=1000, mid=5000, end=8000`，但只跑 4000：

| iter | 墙面 | σ |
|---|---|---|
| 3750（报告窗口均值） | −0.443 | 0.64 |
| **4000（run 结束）** | **≈−0.50** | **≈0.61** |
| 8000（从未到达） | −1.0 | 0.37 |

**整个 run 从未进入低噪声阶段。** 在 0.5 m 半径里精确制动并稳住 1.6 s 需要细控制，σ=0.61 意味着持续大幅动作扰动。这不是旅馆成因（eval 确定性也绕圈），但让"学会刹车"和"学会转身"都更难。

### 4.3 缺失的关键指标：条件完成率

**条件完成率 = 完成驻留局数 / 曾入圈局数**
- v1：10.5% / 54% = **19%**
- 旧策略：≈ 0.48/0.49 = **98%**

这一个数就把问题定位到终点，比 SR 灵敏得多。**必须加入监控，作为 1000 iter 早期闸门。**

## 10. 禁止事项

⛔ 速度门当 P-1 主修法（摊薄后仍 0.58/步，见 §1.3）
⛔ "进圈 6 s 未完成即判失败"（目标常在门洞旁，会把"到门口减速"教成"逃避门口"）
⛔ 启用 `backward_movement_penalty`（#5 已让转身严格优于倒走；启用会封死死胡同脱困与窄处微调）
⛔ 支付门 taper / 放宽 0.8 m / 改走廊半径（`d_path` 0.36 已达标，无实证支持）
⛔ 加 per-step time cost 逼它动（`base_contact` 仍 0.369，会催生冒进）
⛔ 加"楼梯专用奖励"（不泛化；正确做法是让路径在楼梯处几何正确且被判可行）
⛔ 因为 SR 0.105 就回退路径层改动
⛔ 单独上线 #5（会掉进旅馆）或单独上线 #1–4（冻结依旧）
⛔ 现在动 `large_pitch` 阈值（先看 D7）
⛔ 现在开地形课程（先修管线；若 D1 通过 + invalid <8% + 朝向项生效但 stairs SR 仍 ≈0，那时才重新纳入）
⛔ `schedule="adaptive"`（MDPO 未实现，会静默冻结 LR）
⛔ 一次性降 log_std clamp（界外梯度为零，参数钉死在新墙上）
⛔ 同 step 二次调用 `get_all_path_metrics`（非幂等）
⛔ `torch.roll` 做掩码膨胀（首尾串台）
⛔ 新 cfg 字段只赋值不声明（`**kwargs` 静默丢弃）
