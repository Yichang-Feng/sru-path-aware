## 0. 结论

**成功率不是"慢慢变差"，是第 150–200 轮就到过 0.62，随后被两个计量错误吃掉了。**

1. **朝向势函数被采空了**：`heading_progress_to_path` 每回合付出 **15.38**，而它的理论上界是 π=3.14。
   原因是我把"每步增量钳在 0.2 rad"和"`prev := err`"写在一起——**大跳变只收一次钳位（−0.2），
   随后的缓慢回落却按全额付**，于是"让误差跳一下再慢慢修回来"是净赚的（每 16 步约 +1.3，
   一个回合 ≈ 15）。跳变在拐角和目标附近（胡萝卜停在路径末端）最容易制造。
2. **超时罚实际只有 −10，不是 −50**：奖励管理器给每一项都乘 `dt=0.2`，`weight=-50` → −10。
   v1 与 v1.1 的日志都印证：`time_out_penalty = -5.93/回合` ÷ 0.59（超时率）= **−10**。
   于是一边是"+25 完成且回合结束"，另一边是"拖着不完成继续赚 → 只赔 10 分"。

两件事叠加，**"到目标附近绕圈、不完成"重新变成最优**——只不过这次的收入来自朝向项，而不是被清零的接近奖励。

## 3. 因果链（按证据强度）

1. **朝向项突破上界**：15.38 vs π —— 不是估计，是算术。钳位 + `prev := err` 让"大跳变"只赔 0.2，
   而恢复过程全额计费。跳变源：拐角、以及**目标附近胡萝卜停在路径末端**时绕圈造成的方向抖动。
2. **超时只罚 −10**：`weight −50 × dt 0.2`。v1/v1.1 日志一致（−5.93/回合 ÷ 0.59 = −10）。
3. **完成是稀疏的**：+25 一次性，且会结束回合；接近奖励清零后，目标附近**没有任何稠密正信号**，
   只剩 −0.2×速度 的弱负项。策略没有理由去学"停稳 8 步"，而绕圈每步都有 0.045 的朝向收入。
4. 时间吻合：heading 收入 1.28 → 5.40（iter 200–250）→ 15.38，SR 同步 0.62 → 0.50 → 0.10；
   早期（heading 还只有 1.3 时）SR 是全轮次最高点。

**没有被推翻的部分**：接近奖励清零（三项在日志里恒 0）、路径项主导（18.88 vs 1.65）、
`d_path` 0.38、`invalid_seg_frac` 0.076（free mask 修复生效，v1 是 0.22）。

## 4. 修复（已提交）

### 4.1 朝向项改成"有界积分器"

```python
delta = clamp(ref - err, ±0.2)      # 每步仍然不超过 0.2 rad
ref   = clamp(ref - delta, 0, π)    # 参照量只按"实付"移动，并夹在 [0, π]
```

这样整回合 Σdelta = `ref_0 - ref_T`，**严格落在 [−π, π]**，而单步仍然 ≤0.2 rad（不会在拐角爆尖峰）。
新单测 `test_v11_heading_potential_is_bounded_under_a_sawtooth`：连续 10 次"跳 1.3 rad 再慢修"，
总额仍 ≤ π（同样的锯齿输入，旧实现 11.0、新实现 0.0；原地转 180° 两者都是 3.14）。

### 4.2 超时罚改成真正 −50

`time_out_penalty` 权重 −50 → **−250**（×dt=0.2 → −50）。没有改 `episode_time_out` 函数本身，
避免把 Go2W 的惩罚也悄悄放大 5 倍。

### 4.3 偏移走廊 0.5 → 1.5 m

`path_deviation_penalty` 的死区从 0.5 m 放宽到 **1.5 m**（`cap` 1.5 → 2.0，保持到 3.5 m 外仍有梯度）。
理由：机身宽 0.52 m，0.5 m 的走廊根本不够绕过一个新出现的障碍物；而"严格贴线"本来就不是由惩罚项
保证的——是 `progress_along_path` 的**支付门（0.8 m）**在保证：贴线才付钱。惩罚项只是"别乱跑"的护栏。

> 关于"加一个靠近路径的正奖励"：不建议。那是**状态占用型**正奖励（站在路径上就付钱），
> 和本轮刚拆掉的目标旅馆是同一种形状。路径已有的正向信号本身就是"靠近才付"——
> 支付门保证了只有 d<0.8 m 的位移才算进度。若确实还需要额外的塑形，正确形态是**势函数**：
> 付"横向误差的减少量"（总量被初始误差界住，来回摆动净收益为 0），而不是每步按距离付钱。

### 4.3 单测

31 项全过。其中两项旧断言正是"把 bug 写进测试"的：`standing == -10.0` 与
`weights["time_out_penalty"] == -50.0`，已改为 −50 / −250 并注明 dt 关系。
